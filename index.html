BMS 专属

BMS 一首歌是一个文件夹（多个 .bms = 多个难度）；#WAV 找不到的样本不会丢音符，只静音并报警。
键型看通道：11-15 五键、18/19 是第 6/7 键、21-29 是第二人； 16 左手皿、26 右手皿（双人谱里分别在最左、最右）。 自动判定：任一处用到 18/19 就按 7 键，一处都没有就按 5 键 —— 所以「其实是 7K、但这首歌全程没弹第 6/7 键」会被判成 5K，请在「键型」里手动指定 7K / 7K1S。

分层

src/core/            与格式无关的 kernel
  osu/writer.js      ★ 全项目唯一拼 .osu 的地方
  audio.js           混音（audioObjects + samples → PCM）
  encoders/          WAV / MP3(lamejs) / ffmpeg-http
  keysound.js        保留键音（BMS 原生玩法）
  text.js  zip.js  util.js  sampledur.js
src/modes/o2jam/     OJN/OJM 解析 + EX/NX/HX + 异常修正
src/modes/bms/       BMS 文本解析 + 拍/毫秒时间轴
src/ui/shell.js      tab、共用选项、进度、日志、下载

模式只产出数据（timingPoints / hitObjects / audioObjects / meta）， 由 kernel 统一写出 —— 两个模式不会各自长出一套「合法但不一样」的 .osu。

两种来源的差异

  1. 一首歌 = 什么：O2Jam 是一个 .ojn 内含 EX/NX/HX 三段； BMS 是一个文件夹里的多个 .bms，每个就是一个难度。
  2. 时间轴：OJN 用 measure+position 直接累加；BMS 要处理 #BPMxx(03/08)、 #STOP(09) 与 02 小节长度 —— 已在测试里与 .NET 参考实现逐毫秒对齐。
  3. 样本：OJN 在 .ojm 容器里；BMS 的 #WAVxx 指向磁盘文件， 缺文件只静音、不丢音符。
  4. 文本编码：O2Jam 是 GBK 系（连日文也是 GBK）；日系 BMS 多为 Shift-JIS， 所以编码策略跟着模式走，共用同一个下拉框。
  5. 皿/键数：BMS 7K 的第 8 个位置是皿，可摆成 8K 第 0 列，也可只当背景音播。
