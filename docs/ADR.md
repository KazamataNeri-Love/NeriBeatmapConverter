# Architecture Decision Records (ADR) — NeriBeatmapConverter

仅记录影响全局边界、数据契约与治理防线的关键架构决策。新增重大边界调整前须先补一条 ADR。

---

## ADR-001：三层分层与 `Parser → 统一 IR → Emitter` 解耦
- **状态**：已采纳（演进中）
- **背景**：项目已从单文件 O2Jam 工具演进为多格式（O2Jam / BMS）转换台，同时支撑浏览器 UI 与 Node CLI。
- **决策**：
  - 维持 `src/core/`（格式无关 Kernel）+ `src/modes/<format>/`（模式层）+ `src/ui/shell.js`（浏览器外壳）三层架构。
  - 所有格式转换优先遵循 `Parser（格式解析）→ 统一 IR（时间轴/物件/音频对象）→ Emitter（core 写出与打包）` 解耦。
  - `src/core/osu/writer.js` 是全仓唯一允许拼装 `.osu` 文本的模块；公共装配逻辑后续逐步收拢至 `src/core/`，各模式只保留格式差异。
- **后果**：新增模式无需触碰核心写出器与音频管线；任何对 `src/core/` 公共 IR/Writer 的改动都属于高风险变更，必须单独拆单并受盲审红线拦截。

## ADR-002：外部参考工程严格只读与开源许可隔离
- **状态**：已采纳
- **背景**：上级目录 `../_references/` 存放 `BmsToOsu-dev`（AGPL-3.0）与 `o2jam-to-osu`（Java 原版）用于逐毫秒/逐字节核对，而本仓采用 `MIT` 许可。
- **决策**：
  - 所有外部参考工程标记为 `[严格只读]`，仅用于行为对照与格式查证。
  - 严禁将参考工程纳入本仓、引入运行时依赖或复制其源码实现。
- **后果**：保持主仓零运行时依赖与 MIT 许可纯净性。

## ADR-003：Golden 样本库轻量化与大二进制禁入策略
- **状态**：已采纳
- **背景**：现有回归夹具 `../_qa/OfficialBeatmaps/` 含约 23 MB `.ojn`/`.ojm` 音频数据，若直接入仓将导致 Git 历史膨胀且涉及第三方曲包版权风险。
- **决策**：
  - 主仓严禁提交大音频文件、完整曲包压缩包与 `.ojn`/`.ojm` 样本库（已在 `.gitignore` 中作为硬护栏拦截）。
  - 仓内回归与未来 `test/golden/` 仅存极小纯文本谱面（如精简 `.bms` / 合成测试输入）与纯文本 `.osu` 快照。
  - 外部大曲库回归继续通过环境变量 `OJN_ROOT` 在本地按需触发，与仓内自包含测试解耦。
- **后果**：仓库长期保持轻量、干净，且支持无外部大曲库的独立 clone 与 CI 回归。

## ADR-004：转换器数值精度、确定性与音频安全不变量
- **状态**：已采纳
- **背景**：历史排障中多次出现小数时间戳致 osu! 拒导、PCM 浮点→int16 环绕杂音、GBK/Shift-JIS 乱码、ZIP 重名条目致导入失败等隐蔽缺陷。
- **决策**：将以下不变量固化为盲审红线与回归必检项：
  1. 时间轴与坐标严格按约定取整，禁止写出小数时间戳或因缺样本静默丢音符；
  2. PCM 编码统一经 `src/core/encoders/pcm.js` 钳位转换，禁止环绕；
  3. 同一输入在相同参数下必须产出确定性文本与无重名根目录结构的 `.osz`。
- **后果**：任何优化或新特性不得以牺牲确定性或绕过上述防线为代价。

## ADR-005：主仓零依赖与构建产物忽略策略
- **状态**：已采纳
- **背景**：`npm run bundle` 会生成约 376 KB 的单文件 `dist/hub.html`；同时 `vendor/lamejs/lame.min.js`（156 KB）是离线运行必需的静态内嵌库。
- **决策**：
  - 保留 `vendor/lamejs/` 入仓（极小、不变动、保障离线可用）。
  - 将 `dist/` 列入 `.gitignore`（发版时按需 `npm run bundle` 构建或挂 GitHub Release），避免每次修改 `src/` 产生巨量编译产物 diff 干扰 GPT 盲审。
- **后果**：`git diff` 始终仅反映源码与文档改动，单文件产物随时可从源码复现。
